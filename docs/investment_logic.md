# 투자 논리

## 목적과 비목적

이 프로젝트는 공식 데이터와 설명 가능한 규칙을 이용해 사용자가 검토할
후보와 배제 사유를 정리하는 읽기 전용 분석 도구다. 자동주문, 계좌이체,
수익 보장, 개인별 투자자문을 제공하지 않는다.

핵심 순서는 다음과 같다.

1. 데이터 가용성·출처·시점을 검증한다.
2. 강제필터를 점수보다 먼저 적용한다.
3. 통과한 종목에만 범위가 명시된 점수를 계산한다.
4. 시장충격과 시장국면을 별도 분석한다.
5. 신뢰도와 포트폴리오 한도를 적용해 추천 그룹을 만든다.
6. 긍정 근거뿐 아니라 위험·제외·누락 근거를 함께 보존한다.
7. 시점정보가 완전한 입력에 한해서만 백테스트한다.

## 1. 데이터 진실성 게이트

- API 실패, timeout, HTTP 오류와 schema 불일치는 정상 데이터가 아니다.
- 숫자 0과 데이터 누락을 구분한다.
- 원응답과 정규화 데이터를 분리하고 응답·입력 hash를 보존한다.
- 데이터 기준일과 수집시각을 분리한다.
- 기준시점 이후 수집·제출된 정보는 과거 판단에 사용하지 않는다.
- 공식 데이터, 자체 계산값과 설명 추정치를 각각 표시한다.
- 검증되지 않은 통화·단위를 추정하지 않는다.
- 정정공시는 원본을 덮어쓰지 않고 접수번호와 가용 시점을 보존한다.

이 게이트를 통과하지 못한 핵심 입력은 낮은 점수나 0으로 대체하지 않고
`MISSING`, `NOT_VERIFIED`, `CONFLICT` 등으로 계산을 차단한다.

## 2. 종목 유니버스와 강제필터

종목은 KRX 공식 상품·주식종류 필드로 분류한다. 종목명 접미사나 코드 모양으로
ETF·ETN·우선주 등을 추정하지 않는다. 거래정지·관리·상장폐지 위험의 공식
입력이 없으면 안전하다고 가정하지 않는다.

Phase 2 강제필터는 다음 범주를 먼저 확인한다.

- 유동성
- 감사의견과 최신성
- 시장·상장 상태
- 중요 기업 이벤트
- 비금융업 재무위험
- 금융업 별도 모형 입력

결과는 `PASS`, `FAIL`, `MISSING`, `REVIEW_REQUIRED`,
`NOT_APPLICABLE`로 구분한다. 하나라도 blocking 상태면 높은 점수가 이를
상쇄하지 않는다. 세부 규칙은 `scoring_rules.md`에 있다.

## 3. 재무·배당·밸류에이션

재무는 같은 보고기간에서 연결재무제표를 우선하고 공식 조회결과가 없을 때만
별도재무제표를 사용한다. 누적 손익을 분기 단독값처럼 더하지 않으며,
TTM은 필요한 당기누적·전기누적·전기연간 값과 통화가 모두 확인될 때만
계산한다. 순이익과 지배기업 소유주지분 순이익은 다른 지표다.

배당은 OpenDART에 단위가 명시된 확정 현금 DPS만 사용한다. 최근 5개
사업연도, 지급 사업연도, 접수일, 정정 여부와 출처를 함께 본다. 공식 추정
DPS가 없으면 추정값을 만들지 않는다.

산업 PER·PBR은 공식 산업분류와 최소 표본을 요구한다. 양수 유효 표본만
사용하고 소표본이면 상위 산업으로 fallback하거나 비교 불가로 둔다.
음수 PER에는 저평가 점수를 주지 않는다. 산업분류가 없는 현재 환경에서는
이 계산의 운영 완료를 주장하지 않는다.

## 4. 점수의 의미

Phase 2의 `PHASE2_CORE_ONLY`는 배당·재무·밸류에이션 70점 구성 내부를
100점 척도로 정규화한 값이다. 프로젝트 전체 투자매력 100점이 아니다.

각 구성요소는 다음을 저장한다.

- 원시값 또는 원문 상태
- 정규화값
- 가중치
- 기여점
- 출처와 근거
- 계산 불가 사유

데이터 신뢰도는 완전성, 최신성, 공식 출처, 교차검증, 산업 표본,
수정가격 확인과 계정 매핑을 본다. 신뢰도 기준 미달이면 추천하지 않는다.

## 5. 시장충격·반도체·시장국면

시장 분석은 KOSPI 지수, 전체 종목 수정가격과 공식 산업분류를 같은
기준시점으로 맞춘다. 21·63·126·252거래일 고점과 낙폭, 상승종목 비율,
중앙수익률, 이동평균 상회 비율을 함께 본다.

공식 반도체 지수가 있으면 정확히 같은 계산구간의 공식 수익률을 사용한다.
없으면 공식 산업분류 정확 코드로만 자체 바스켓을 만들고
`SELF_CALCULATED_PROXY`라고 표시한다. 종목명이나 삼성전자·SK하이닉스
두 종목만으로 반도체 모집단을 만들지 않는다.

종목별 기여도는 전일 시가총액 비중×당일 수정가격 수익률의 설명
추정치이며 공식 지수 포인트나 인과관계가 아니다.

시장국면은 적색(투매), 주황(안정화), 황색(회복), 녹색(순환상승)과
불확실로 구분한다. 반도체 회복, KOSPI 회복, 비반도체 확산과 배당주
상대강도를 별도로 표시한다. 두 대형 반도체주만 상승하면 완전한 회복으로
판정하지 않는다. 세부 임계값은 `market_regime_rules.md`에 있다.

## 6. 추천과 포트폴리오

추천은 강제필터, `PHASE2_CORE_ONLY`, Phase 3 시장국면, 데이터 신뢰도와
사용자 한도를 같은 기준시점으로 결합한다.

추천 그룹은 다음 여섯 가지다.

- 회복 준비 완료
- 우량하지만 관망
- 과도할인 후보
- 일반 검토
- 투자배제
- 데이터 부족

과도할인 후보는 같은 기간의 비반도체 동일가중 수익률 대비 상대하락을
뜻할 뿐 숨은 악재 부재나 반등 인과를 증명하지 않는다. 적극추천 대신 추가
공시 검토 상태로 둔다.

포트폴리오는 종목·산업·확인된 기업집단 최대비중, 배당주·성장주·현금
목표비중과 시장국면별 목표를 적용한다. 기업집단 입력이 없으면 해당 한도를
검증했다고 표시하지 않는다.

분할매수 계획은 검증 수정종가를 참고가격으로만 사용하고 회차별 실행조건과
전체 취소조건을 제공한다. 목표가격을 임의 생성하지 않으며
`is_order_executable=false`를 DB에서 강제한다. 세부 규칙은
`recommendation_rules.md`에 있다.

## 7. 공시·뉴스·애널리스트·수급

공식 공시를 우선하고 뉴스와 참고 데이터를 구분한다. 뉴스는 네이버 API가
제공한 제목과 요약만 사용한다. 기사 본문을 읽은 것처럼 표현하지 않는다.
긍정·중립·부정은 구조화된 키워드 규칙의 설명 결과이며 사실 검증, 주가
인과나 점수가 아니다.

증권사 투자의견·목표주가는 추정 참고 데이터이고 외국인·기관·개인의 실제
매매와 다르다. 프로그램매매, 공매도도 각각 공식 필드가 확인된 값만
저장한다. EPS·대차·신용처럼 안전한 계약이 없는 숫자는 만들지 않는다.

현재 Phase 5 참고 데이터를 Phase 4 점수에 소급 결합하지 않는다.

## 8. 백테스트

백테스트는 현재 종목 목록을 과거 전체에 적용하지 않는다. 다음을 명시한
`BacktestDataset`만 계산한다.

- 시점별 종목 유니버스와 상장폐지 포함 여부
- 공시 제출일과 정정공시 가용 시점
- 검증 수정가격과 통화
- 확정 현금배당 지급일
- 공식 상장폐지 정산값
- 같은 기간 벤치마크
- 과거 추천 snapshot과 rule/version

신호 다음 거래일의 수정시가로 진입하고 거래비용을 반영한다. 배당은
보유기간 중 지급된 확정 현금 DPS만 포함한다. 상장폐지 정산이나 시점
이력이 불완전하면 임의 0원·마지막 종가로 대체하지 않고 실행 전체를
`MISSING`으로 둔다.

같은 config·입력·버전은 같은 hash와 결과를 재사용한다. 현재 실제
point-in-time corpus가 없어 생존편향 제거 완료나 실제 성과를 주장하지 않는다.

## 9. 사용자가 확인해야 할 것

추천 또는 결과를 검토할 때 최소한 다음을 함께 확인한다.

- 출처, 기준일과 수집시각
- 실시간·지연·전일종가 구분
- 공식 지수 또는 자체 프록시 여부
- 강제필터 통과·실패·누락
- 점수 범위와 rule/version
- 긍정 근거와 반대·위험 근거
- 데이터 신뢰도와 계산 가능 여부
- 알려진 제약과 외부 데이터 미확보 상태

20개 최종 완료 기준의 현재 판정은 `FINAL_COMPLETION_CHECKLIST.md`에 있다.
