## 2. 계약은 확인했지만 실제 응답 검증이 필요한 항목

### KRX 수치 단위

KRX 종목기본정보·일별매매정보·KOSPI 지수의 공식 다운로드 명세에서 필드명과 문자열 형식은 확인했지만 통화·수량 단위를 명시한 열을 확인하지 못했다. `ACC_TRDVAL`, `MKTCAP`, `LIST_SHRS`, `PARVAL`을 이름만 보고 원·주 단위라고 고정하지 않는다.

안전한 처리:

1. 인증키로 최소 호출한다.
2. 인증정보를 제거한 원응답을 저장한다.
3. 동일 기준일의 KRX 공식 화면 또는 공식 데이터 사전과 대조한다.
4. 단위가 확정될 때까지 정규화 필드의 품질상태를 `NOT_VERIFIED`로 둔다.

### OpenDART 배당 행과 재무 계정

`alotMatter.json`은 `se`에 여러 배당 항목을 행으로 반환하고 전역 단위 필드가 없다. 회사·보고서별 공시 표현 차이를 실제 스냅샷으로 검증해야 한다.

`fnlttSinglAcntAll.json`의 `currency`는 통화를 제공하지만 다음 문제는 별도 처리가 필요하다.

- XBRL 표준계정과 기업 확장계정의 매핑
- 연결(CFS)과 별도(OFS) 구분
- 분기·반기 누적값과 단독 분기값 구분
- 정정공시의 원본·정정본 보존
- 공시되지 않은 계정을 0으로 만들지 않는 결측 처리

### 한국투자증권 단위와 시점

현재가·기간별시세 계약은 숫자를 문자열로 반환하며 개별 필드의 형식은 있지만 모든 값에 적용되는 단위 메타필드는 없다. 또한 REST 현재가 계약은 실시간이 필요하면 WebSocket을 사용하라고 명시한다.

따라서:

- 응답 수신시각을 `Asia/Seoul`로 저장한다.
- REST 현재가를 실시간 체결가라고 표현하지 않는다.
- 일별값은 KRX 장 마감 확정값과 대조한다.
- `hts_avls`, `acml_tr_pbmn`, 가격·수량 필드는 실제 응답과 공식 설명으로 단위를 확정한다.

### ECOS 통계표·항목코드

`StatisticSearch`의 공통 계약은 확인했지만 기준금리·국고채 금리·환율·경기지표의 정확한 통계표 코드와 항목 코드는 아직 확정하지 않았다. 검색결과나 관행적인 코드값을 하드코딩하지 않는다.

각 시리즈는 다음을 함께 고정해야 한다.

- 통계표코드
- 항목코드 1~4
- 주기
- `UNIT_NAME`
- `TIME` 형식
- 최초·최종 제공기간
- 원 통계작성기관과 상업적 이용 제한 여부

## 3. 원문 파싱이 필요한 항목

| 원문 | 필요한 결과 | 주요 위험 | 필수 보존정보 |
|---|---|---|---|
| OpenDART 현금·현물배당결정 | DPS, 총액, 배당기준일, 지급예정일, 주식종류 | 정정공시, 보통주/우선주 혼합, 단위, 미확정 이사회 결의 | 원·정정 접수번호, 원문, 공시일, 기준일, 단위 |
| OpenDART 감사보고서 | 계속기업 불확실성, 내부회계 문제 | 문맥을 잃은 키워드 오탐, 감사의견과 강조사항 혼동 | 접수번호, 감사인, 감사의견, 원문 문단 |
| OpenDART 주요사항보고서·거래소공시 | 영업정지, 횡령·배임, 소송, 증자, CB/BW, 최대주주 변경 | 구조화 API가 있어도 세부조건은 원문에만 존재할 수 있음 | 사건일, 공시일, 금액·비율·단위, 정정 관계 |
| 재무제표 주석·XBRL | 차입금, CAPEX, 금융업 규제비율, 일회성 손익 | 기업 확장계정, 표 단위, 연결범위, 기간 | 계정 ID, 컨텍스트, 단위, 연결/별도, 기간 |
| KIND 공식 화면·공시 | 시장상태 교차검증 | 공개 API·자동수집 권한 미확인 | 자동화하지 않고 수동 확인 결과와 공식 링크만 기록 |

원문 파싱은 파싱 실패를 0이나 정상상태로 바꾸지 않는다. 실패 시 `MISSING`, `NOT_VERIFIED`, `CONFLICT` 중 적절한 상태를 반환한다.

## 4. 라이선스와 재배포 제한

### KRX

- Open API 약관의 비상업적 이용, 출처 표시, 제3자 제공 제한을 적용한다.
- 실시간·지연 시세, 재배포, 수익 목적 이용은 별도 데이터 이용계약이 필요한지 확인한다.
- 원응답을 저장하는 것과 외부 사용자에게 원자료를 재배포하는 것은 구분한다.

### OpenDART

- 서비스키를 저장소·로그·응답에 노출하지 않는다.
- 공시자료의 정확성·완전성을 제공기관이 보증하는 것으로 표현하지 않는다.
- 원문 링크와 접수번호를 제공해 사용자가 직접 확인할 수 있게 한다.

### 한국투자증권

- 앱키·앱시크릿·접근토큰·계좌번호를 원자료나 로그에 저장하지 않는다.
- 데이터의 제3자 제공·상업 서비스 이용 범위는 계정 유형과 제휴계약을 별도 확인한다.
- 현재 프로젝트는 읽기 전용이며 주문·계좌 쓰기는 구현하지 않는다.

### NAVER

- 검색결과의 제목·요약은 기사 본문 라이선스를 부여하지 않는다.
- 원문 링크와 제공시각을 보존하고 과도한 장기 캐시·재배포는 이용조건을 확인한다.
- 운영 신규 연동은 NAVER API HUB 계약을 기준으로 하며 레거시 개발자센터 경로에 신규 설계를 고정하지 않는다.

### ECOS

- 출처를 한국은행 ECOS로 표시한다.
- 상업적 이용 제한이 표시된 통계는 원 통계작성기관 승인을 확인한다.
- 통계의 수정·개편 가능성을 고려해 수집시각과 응답 해시를 보존한다.

## 5. 인증정보가 확보될 때의 최소 검증 절차

각 기관마다 읽기 전용의 최소 요청 1건만 먼저 수행한다.

1. 공식 문서의 현재 계약과 호출 제한을 다시 확인한다.
2. 비밀값은 환경변수로만 읽고 명령·로그에 출력하지 않는다.
3. timeout, 제한된 retry, exponential backoff, rate limiter를 적용한다.
4. HTTP 상태와 제공기관의 응답 상태코드를 각각 검증한다.
5. Pydantic 등으로 계약 필드와 타입을 검증한다.
6. 인증 헤더·키·계좌 식별정보를 제거한다.
7. 원응답과 SHA-256 해시, 요청 파라미터 해시, 수신시각, 데이터 기준일을 저장한다.
8. KRX·KIS·DART 등 겹치는 값은 동일 기준시점과 단위로 대조한다.
9. 불일치가 허용범위를 넘으면 `CONFLICT`로 남기고 숫자를 선택하지 않는다.

현재는 모든 인증키가 미설정이므로 이 절차를 실행하지 않았고 실제 응답 스냅샷도 만들지 않았다.

## 6. MVP 보류 항목

- 자동 추천과 추천 종목 목록
- 포트폴리오 비중과 분할매수 가격
- 실제 데이터가 없는 점수·시장국면·반도체 충격 판정
- 애널리스트 컨센서스 기반 예상 배당
- 실시간 전 종목 구독
- 자동주문·계좌 쓰기
- 생존편향 보정 백테스트
- 뉴스 본문 NLP와 생성형 AI 판정

Phase 3 계산 코드는 구현됐지만 공식 산업분류 writer, 검증된 수정가격,
실제 KRX 지수 입력이 없으면 시장국면·반도체 충격을 `불확실`로 유지하고
샘플 숫자를 만들지 않는다.
