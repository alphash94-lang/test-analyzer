당신은 한국 주식시장 데이터에 전문성이 있는 시니어 퀀트 개발자,
금융데이터 엔지니어, 재무분석가, 백엔드 개발자이자
Streamlit 기반 웹 애플리케이션 개발자다.

지금부터 실제 투자 의사결정에 참고할 수 있는
“코스피 배당주·성장주 투자분석 프로그램”을 개발하라.

프로젝트의 가칭은 다음과 같다.

KOSPI Dividend & Semiconductor Rotation Analyzer
한국어 표시명:
“코스피 배당주 저평가·시장회복 분석기”

==================================================
1. 프로젝트의 핵심 목적
==================================================

이 프로그램의 핵심 투자 가설은 다음과 같다.

최근 코스피가 반도체 주도로 크게 상승한 뒤 반도체 관련 충격으로 급락하면서,
기업의 배당능력과 재무상태에는 큰 변화가 없는 우량 배당주까지
시장 전체의 투매에 휩쓸려 동반 하락했을 가능성이 있다.

따라서 프로그램은 다음 종목을 찾아야 한다.

1. 코스피에 상장된 일반 주식
2. 실제로 현금배당을 지급하는 종목
3. 배당이 일회성이 아니라 지속 가능할 가능성이 높은 종목
4. 감사의견과 재무상태에 중대한 문제가 없는 종목
5. 산업 평균과 기업의 과거 수준에 비해 저평가된 종목
6. 기업 고유의 악재보다 시장·반도체 충격 때문에 과도하게 하락한 종목
7. 거래량과 거래대금이 충분해 실제 매매가 가능한 종목
8. 시장과 반도체가 안정화될 때 분할매수하기 좋은 종목

성장주 포트폴리오는 반도체를 중심으로 간략하게 구성하되,
전체적으로는 배당주 중심 포트폴리오를 목표로 한다.

중요:
“코스피가 9,000에서 5,000대로 떨어졌다.”
“이번 하락은 반도체 때문이다.”
라는 문장은 프로그램의 고정 전제로 사용하지 않는다.

이것들은 검증해야 할 투자 가설이다.

프로그램을 실행할 때마다 실제 시장 데이터로 다음을 다시 계산하라.

- 최근 21거래일, 63거래일, 126거래일, 252거래일 고점
- 현재 지수
- 고점 대비 낙폭
- 고점 날짜
- 반도체 종목군 수익률
- 비반도체 코스피 수익률
- 코스피 동일가중 수익률
- 코스피 종목 중앙수익률
- 상승 종목 비율
- 20일 이동평균선 위 종목 비율
- 반도체 종목의 지수 하락 기여도
- 배당주 종목군의 동반 하락 정도

==================================================
2. 절대적인 데이터 원칙
==================================================

이 프로그램은 실제 투자 참고용이므로 다음 원칙을 절대 위반하지 마라.

2-1. 실제 데이터만 사용

운영 화면에 다음 데이터를 절대로 사용하지 마라.

- 임의로 만든 샘플 주가
- 무작위 생성 데이터
- 하드코딩된 재무제표
- 가상의 배당금
- 존재하지 않는 API 응답
- 추정해서 만든 감사의견
- API 오류를 0으로 바꾼 값
- 오래된 예시 데이터를 현재 데이터인 것처럼 표시하는 행위

API 키가 없거나 API 호출에 실패하면 다음과 같이 표시하라.

“데이터 연결 필요”
“데이터 수집 실패”
“최신 데이터 확인 불가”
“핵심 데이터가 없어 추천을 계산할 수 없습니다.”

절대로 임의의 숫자로 빈칸을 채우지 마라.

2-2. 현재 시장 수치를 하드코딩하지 말 것

현재 코스피, 최근 고점, 현재 낙폭, 삼성전자·SK하이닉스 가격,
RSI, PER, PBR, 배당수익률 등을 코드에 고정하지 마라.

모든 값은 실행 시점의 실제 데이터에서 계산한다.

2-3. 모든 숫자의 출처와 기준일 표시

화면에 표시되는 모든 주요 숫자에는 최소한 다음 메타데이터가 있어야 한다.

- 데이터 출처
- 데이터 기준일 또는 기준시각
- 프로그램 수집시각
- 실시간, 지연, 전일종가 중 어느 것인지
- 연결재무제표 또는 별도재무제표 여부
- 확정값 또는 추정값 여부
- 공시 접수번호 또는 원문 링크
- 데이터 품질 상태

예:

현재가: 71,300원
출처: 한국투자증권 Open API
가격 기준시각: 2026-07-28 14:32:10 KST
수집시각: 2026-07-28 14:32:12 KST
상태: 실시간

배당금: 주당 2,500원
출처: OpenDART 현금·현물배당결정 공시
사업연도: 2025
공시 접수일: YYYY-MM-DD
상태: 확정

2-4. 데이터가 오래됐으면 경고

장중 실시간 가격이 일정 시간 이상 갱신되지 않으면
“가격 데이터 지연” 경고를 표시하라.

최근 재무제표나 감사보고서가 없으면
과거 자료로 자동 추천하지 말고 데이터 부족을 표시하라.

2-5. API 주소와 필드명을 추측하지 말 것

공식 API 문서를 확인하지 않은 상태에서
endpoint, request parameter, response field를 임의로 만들지 마라.

개발 시작 전에 반드시 다음 문서를 작성하라.

docs/api_contract.md

이 문서에는 다음을 기록한다.

- 제공기관
- 공식 API 기능명
- 실제 endpoint
- 인증 방식
- 요청 변수
- 응답 필드
- 호출 제한
- 데이터 갱신주기
- 필드 단위
- 실제 테스트 성공 여부
- 대체 데이터 출처
- 확인한 공식 문서 기준일

필요한 데이터가 공식 API에 없다면
가짜 endpoint를 만들지 말고 다음 중 하나를 선택한다.

1. 다른 공식 API를 사용한다.
2. 원 공시문서를 파싱한다.
3. 해당 지표를 계산하지 않고 “데이터 없음”으로 표시한다.
4. 기능을 보류하고 그 사유를 문서화한다.

2-6. 테스트 데이터 원칙

단위 테스트에서 fixture가 필요하다면
실제 API 응답을 개인정보와 인증정보만 제거한 뒤 저장한
실제 응답 스냅샷을 사용한다.

운영 추천에 합성 시계열이나 무작위 데이터를 사용하지 마라.

2-7. 숫자가 같은 의미인지 검증

KRX, 한국투자증권, OpenDART, KIND의 값이 서로 다르면
무조건 하나를 선택하지 말고 다음을 확인한다.

- 기준시각 차이
- 연결·별도 차이
- 수정공시 여부
- 단위 차이
- 액면분할·무상증자 반영 여부
- 보통주·우선주 구분
- 최근 결산기 차이

차이가 허용범위를 넘으면 데이터 불일치 경고를 표시한다.

3. 공식 데이터 출처
==================================================

데이터 출처의 우선순위는 다음과 같다.

3-1. KRX Open API 및 KRX Data Marketplace

사용 목적:

- 코스피 종목 기본정보
- 상장일
- 시장구분
- 보통주·우선주 및 상품구분
- 일별 시가·고가·저가·종가
- 거래량
- 거래대금
- 시가총액
- 상장주식수
- 코스피 지수
- KRX 및 KOSPI 계열 지수
- ETF·ETN 등의 상품 제외
- 투자주의·경고·위험 여부 확인
- 관리종목
- 거래정지
- 공매도 관련 데이터
- 투자자별 거래 데이터가 공식적으로 제공되는 경우 활용

3-2. 한국투자증권 Open API

사용 목적:

- 현재가
- 실시간 체결가
- 실시간 호가
- 일·주·월·년 기간별 시세
- 국내업종 지수
- 기관·외국인 수급
- 프로그램매매
- 공매도 추이
- 신용잔고
- 종목별 투자의견
- 증권사별 투자의견
- 목표주가
- 종목 추정실적
- 배당일정
- 기업행사 일정

실시간 데이터는 한국투자증권 API를 우선 사용하고,
장 마감 후 확정 일별 데이터는 KRX 자료와 대조한다.

이 프로그램은 초기에는 읽기 전용으로 개발한다.

자동주문, 매수주문, 매도주문, 계좌이체 기능은 구현하지 마라.
계좌번호가 없어도 가능한 분석 기능과 시세 기능부터 개발한다.

3-3. OpenDART

사용 목적:

- 기업 고유번호와 종목코드 연결
- 공시 검색
- 사업보고서
- 반기보고서
- 분기보고서
- 연결재무제표
- 별도재무제표
- 배당에 관한 사항
- 현금·현물배당결정
- 감사인의 명칭
- 감사의견
- 계속기업 관련 불확실성
- 자기주식 취득·처분
- 유상증자
- 무상증자
- 감자
- 전환사채
- 신주인수권부사채
- 영업정지
- 횡령·배임
- 주요 소송
- 합병·분할
- 최대주주 변경 관련 공시
- 실적 관련 공시

OpenDART에서 추출한 요약값만 사용하지 말고,
중요한 투자배제 사유는 원 공시 접수번호와 보고서 내용을
사용자가 직접 확인할 수 있도록 연결한다.

정정공시가 존재할 경우 가장 최근 정정공시를 우선하되,
원 공시와 정정 내역을 모두 보존한다.

3-4. KIND

사용 목적:

- 관리종목
- 매매거래정지
- 불성실공시법인
- 투자주의·투자경고·투자위험
- 횡령 관련 투자유의사항
- 최대주주 빈번 변경
- 상장폐지 관련 상태
- 배당정보 교차검증
- 기업 밸류업 공시
- 자사주 관련 정보

3-5. 네이버 뉴스 검색 공식 API

사용 목적:

- 최근 종목 뉴스 검색
- 기사 제목
- 기사 요약
- 기사 제공시각
- 기사 링크
- 공시 이후 관련 보도 확인

네이버 금융 페이지를 반복 크롤링하는 방식은
주 데이터 수집 수단으로 사용하지 마라.

뉴스 API에서 기사 본문 전체를 제공하지 않는 경우
제목과 제공된 요약만 분석하고,
기사 전체 내용을 읽은 것처럼 표현하지 마라.

3-6. 한국은행 ECOS 또는 공식 거시경제 데이터

선택적 사용 목적:

- 기준금리
- 국고채 금리
- 원·달러 환율
- 경기 관련 주요 지표

거시지표는 종목의 강제 배제조건이 아니라
시장상황 참고지표로 사용한다.

3-7. 비공식 데이터의 사용 제한

다음은 주 데이터의 원천으로 사용하지 마라.

- 무단 네이버 금융 크롤링
- 출처 불명의 블로그
- 커뮤니티 게시글
- AI가 생성한 투자정보
- 출처가 불명확한 무료 데이터
- 임의 수정된 CSV
- yfinance의 한국주식 데이터를 단독 원천으로 사용하는 방식
- pykrx를 공식 원천처럼 표시하는 방식

비공식 라이브러리는 공식 데이터를 검증하거나
개발 편의를 위한 보조수단으로만 사용할 수 있다.

4. 인증키와 보안
==================================================

API 키는 소스코드에 직접 적지 마라.

다음 환경변수를 사용하라.

KRX_API_KEY=
DART_API_KEY=
KIS_APP_KEY=
KIS_APP_SECRET=
KIS_ACCOUNT_NO=
NAVER_CLIENT_ID=
NAVER_CLIENT_SECRET=
DATABASE_URL=

`.env` 파일은 Git에 올리지 않는다.

`.env.example`에는 변수명만 기록한다.

로그에 API 키, 토큰, 계좌번호, 개인식별정보를 출력하지 마라.

API 키가 설정되지 않은 경우
애플리케이션 첫 화면에 데이터 연결 상태를 표시한다.

예:

KRX: 연결되지 않음
OpenDART: 연결되지 않음
한국투자증권: 연결되지 않음
네이버 뉴스: 연결되지 않음

연결되지 않은 상태에서 예시 종목이나 가짜 숫자를 보여주지 마라.

5. 투자 대상 종목
==================================================

기본 투자 유니버스는 다음과 같다.

- 한국거래소 유가증권시장 KOSPI 상장 주식
- 일반 상장 보통주
- 실제 거래 중인 종목

기본 제외 대상:

- ETF
- ETN
- ELW
- 스팩
- 신주인수권증권
- 신주인수권증서
- 상장폐지 종목
- 거래정지 종목
- 관리종목
- 감사보고서 확인 불가 종목
- 핵심 재무데이터 확인 불가 종목

우선주는 ETF는 아니지만 유동성과 의결권 구조가 다르므로
기본값에서는 제외하고 사용자 설정으로 포함할 수 있게 한다.

리츠 역시 일반 제조업과 평가 방식이 다르므로
기본값에서는 별도 전략군으로 분리한다.

7. 재무제표 처리 원칙
==================================================

7-1. 연결재무제표 우선

연결재무제표가 있으면 연결재무제표를 사용한다.
연결재무제표가 없을 때만 별도재무제표를 사용하고
화면에 명확히 표시한다.

7-2. TTM 계산

최근 12개월 TTM 실적을 계산한다.

분기보고서의 손익계산서와 현금흐름표는
누적값으로 제출되는 경우가 있으므로 다음을 정확히 처리한다.

- 1분기: 1분기 누적값
- 2분기 단독값: 반기 누적값 - 1분기 누적값
- 3분기 단독값: 3분기 누적값 - 반기 누적값
- 4분기 단독값: 연간값 - 3분기 누적값

누적값을 분기 단독값처럼 더해서
실적을 이중계산하지 마라.

7-3. 정정공시

정정된 재무제표가 있으면 최신 정정본을 사용한다.
원본과 정정본의 접수번호 및 변경내역을 보존한다.

7-4. 계정과목 매핑

기업마다 한글 계정과목 명칭이 다를 수 있으므로
가능하면 XBRL 표준 계정 ID를 기준으로 매핑한다.

다음 계정은 매핑 테이블을 별도로 관리한다.

- 매출액
- 영업수익
- 영업이익
- 당기순이익
- 지배기업 소유주지분 순이익
- 자산
- 부채
- 자본
- 지배기업 소유주지분
- 영업활동현금흐름
- 유형자산 취득
- 무형자산 취득
- 이자비용
- 현금 및 현금성자산
- 단기·장기차입금
- 현금배당금 지급액

계정 매핑에 실패하면 0을 넣지 말고
data_quality 상태를 낮추고 사용자에게 표시한다.

8. 필수 투자배제 조건
==================================================

강제 배제조건은 점수가 높다고 상쇄하지 않는다.

다음 중 하나에 해당하면 기본적으로 투자 대상에서 제외한다.

8-1. 상품 및 시장 조건

- 코스피 일반 주식이 아님
- ETF, ETN, ELW, 스팩 등에 해당
- 상장폐지
- 거래정지
- 관리종목
- 실질심사 대상 등 중대한 시장 상태

8-2. 감사의견

최근 12개월 내 제출된 감사보고서 또는
가장 최근 사업연도 감사보고서를 확인한다.

다음은 투자배제:

- 한정의견
- 부적정의견
- 의견거절
- 감사보고서 미제출
- 최신 감사의견 확인 불가
- 계속기업 존속능력에 중대한 불확실성이 있고 위험도가 높다고 판단되는 경우

적정의견이라도 다음 내용을 별도 경고한다.

- 계속기업 관련 강조사항
- 중요한 내부회계관리제도 문제
- 감사인 변경
- 핵심감사사항 중 중대한 위험

8-3. 유동성

거래량만 보지 말고 거래대금을 사용한다.

기본 필터값은 사용자 설정 가능하게 한다.

초기 기본값:

- 최근 60거래일 일평균 또는 중앙 거래대금 10억원 이상
- 최근 20거래일 중 거래량 0인 날이 없어야 함
- 1회 주문예정금액이 20일 중앙 거래대금의 0.5% 이하여야 함

평균은 극단값 영향을 받으므로
중앙 거래대금을 함께 사용한다.

장중 호가데이터가 있으면 다음도 표시한다.

- 매수·매도 호가 스프레드
- 상위 호가잔량
- 예상 시장충격

8-4. 재무위험

비금융업:

이자보상비율 = 영업이익 / 이자비용

다음 조건을 검토한다.

- 1배 미만이 지속되는 경우 배제
- 영업손실이 반복되는 경우 배제 또는 수동검토
- 산업 하위 20%이면 감점
- 산업 중앙값보다 높으면 불이익을 주지 않음
- 이자비용이 거의 없으면 0으로 나누지 말고 무차입 또는 저차입 상태로 표시

금융업에는 일반 이자보상비율을 적용하지 않는다.

은행, 보험, 증권에는 별도 평가모형을 사용한다.

금융업의 필요 지표가 실제 공시에서 확인되지 않으면
임의 추정하지 말고 데이터 부족으로 표시한다.

8-5. 심각한 기업 이벤트

다음 공시는 투자배제 또는 수동검토 대상으로 한다.

- 횡령·배임
- 대규모 유상증자
- 반복적인 전환사채·신주인수권부사채 발행
- 대규모 손상차손
- 영업정지
- 부도
- 회생절차
- 자본잠식
- 최대주주 빈번 변경
- 중대한 소송
- 배당 중단 가능성을 높이는 실적 악화

9. 배당주 분석
==================================================

단순 배당수익률 순위를 만들지 마라.

주가 급락으로 배당수익률만 높아진
“배당 함정”을 구분해야 한다.

다음 지표를 실제 데이터로 계산한다.

- 최근 확정 DPS
- 최근 3년 DPS
- 최근 5년 DPS
- 최근 5년 중 배당 지급연도 수
- 배당 연속성
- 최근 배당 삭감 여부
- 3년 DPS 성장률
- 5년 DPS CAGR
- 현재 확정 배당수익률
- 최근 12개월 배당수익률
- 회사 발표 또는 실제 컨센서스가 있을 때만 예상 배당수익률
- 배당성향
- FCF 배당성향
- 현금배당 총액
- 영업현금흐름 대비 배당금
- 순현금 또는 순차입금
- 자사주 취득
- 자사주 소각
- 총주주환원율

예상 배당금은 공식 공시 또는 실제 추정실적 데이터가 없으면 만들지 마라.

배당성향:

현금배당총액 / 지배기업 소유주지분 당기순이익

FCF:

영업활동현금흐름
- 유형자산 취득
- 무형자산 취득

FCF 배당성향:

현금배당총액 / FCF

분모가 음수거나 지나치게 작으면
배당성향을 정상 숫자처럼 표시하지 말고 위험 경고를 표시한다.

11. 산업 평균 PER·PBR 및 저평가 분석
==================================================

산업분류는 공식 KRX 또는 공식 종목 마스터에 있는
산업분류를 우선 사용한다.

산업분류 출처를 종목별로 저장한다.

산업 평균을 계산할 때 단순 평균만 사용하지 마라.

다음을 계산한다.

- 산업 중앙 PER
- 산업 중앙 PBR
- 산업 중앙 EV/EBITDA
- 산업 중앙 ROE
- 산업 중앙 이자보상비율
- 각 지표의 산업 내 백분위
- 종목의 최근 3년 또는 5년 자체 밸류에이션 중앙값
- 종목의 현재 밸류에이션이 자체 역사에서 어느 백분위인지

극단값은 winsorizing 또는 사분위 기반 방식으로 완화한다.

기본 원칙:

- 순이익이 음수이면 PER를 N/M으로 처리
- 자본이 음수이면 PBR 비교에서 제외
- PER가 음수라고 싸다고 평가하지 않음
- 금융업은 PBR과 ROE를 중심으로 평가
- 경기민감업종은 고점 이익 기준 저PER 함정을 경고
- 반도체는 정상화 이익과 업황 사이클을 별도 표시

산업 표본이 너무 작으면
세부 산업 대신 상위 산업분류를 사용하고 이를 표시한다.

산업 비교 최소 표본 수는 기본 10개로 하되 설정 가능하게 한다.

적정가치는 단일 숫자가 아니라 범위로 표시한다.

- 보수적 적정가
- 기준 적정가
- 낙관적 적정가

다음 방법을 조합한다.

- 산업 중앙 PER
- 산업 중앙 PBR
- 자체 과거 PER·PBR 범위
- ROE와 PBR 관계
- 안정적인 배당주의 경우에만 보수적 배당할인모형
- 실제 애널리스트 컨센서스가 존재하면 참고값으로 별도 표시

적정가치는 수익 보장이 아니라
가정에 따른 평가 범위라는 점을 명시한다.

12-1. 시장 고점과 낙폭 자동 탐지

12-2. 반도체 종목군

공식 KRX 반도체 지수 또는 공식 산업분류를 우선 사용한다.

공식 반도체지수가 이용 불가능하면
산업분류상 반도체 종목으로 자체 바스켓을 구성한다.

이 경우 반드시 “자체 반도체 프록시 지수”라고 표시한다.

삼성전자와 SK하이닉스만으로
전체 반도체 업종을 대표한다고 단정하지 마라.

반도체 바스켓은 다음 두 방식으로 계산한다.

- 시가총액 가중
- 동일가중

12-3. 반도체 제외 코스피

코스피 종목 중 반도체 분류 종목을 제거한 뒤
다음을 자체 계산한다.

- 비반도체 시가총액 가중지수
- 비반도체 동일가중지수
- 비반도체 종목 중앙수익률

12-4. 시장 하락 기여도

종목별 전일 시가총액 비중과 수익률을 이용해
지수 기여도를 계산한다.

종목 기여도:

전일 지수 내 비중 × 당일 종목 수익률

반도체 기여도:

반도체 종목 기여도의 합

다음 결과를 표시한다.

- 코스피 전체 수익률
- 반도체 바스켓 수익률
- 비반도체 바스켓 수익률
- 반도체의 하락 기여도
- 삼성전자의 기여도
- SK하이닉스의 기여도
- 하락 종목 수
- 상승 종목 수
- 종목 중앙수익률

“반도체 때문에 하락했다”라는 결론은
데이터가 뒷받침할 때만 표시한다.

예시 분류:

반도체 주도 하락:
- 반도체 종목의 음의 기여도가 전체 음의 기여도의 상당 부분을 차지
- 반도체 바스켓이 비반도체 바스켓보다 현저히 부진
- 반도체 대형주의 시가총액 기여도가 높음

시장 전반 투매:
- 비반도체 동일가중지수도 큰 폭 하락
- 하락 종목 비율이 매우 높음
- 종목 중앙수익률도 크게 음수
- 배당주·방어주도 동반 하락

혼합형:
- 반도체가 하락을 시작했지만 비반도체로 매도가 확산

불확실:
- 필요한 데이터가 부족하거나 기여도 차이가 명확하지 않음

분류 기준은 config 파일로 관리하고
백테스트를 통해 조정 가능하게 한다.

- 배당·실적·재무상태 양호
- 기관 또는 외국인 수급 상대적으로 안정
- 변동성이 비교적 낮음

B. 시장충격으로 과도하게 할인된 배당주

- 시장이나 산업보다 더 하락
- 기업 고유의 중대한 악재 공시 없음
- 배당과 현금흐름 유지
- 감사의견 적정
- 밸류에이션 할인 확대
- 거래량과 유동성 충분
- 가격 안정화 신호 확인 필요

산업보다 지나치게 더 하락한 종목은
숨은 악재가 있을 수 있으므로 자동 적극추천하지 말고
“과도할인 후보·추가검토”로 분류한다.

12-6. 하락원인 추정치

다음 구성으로 하락원인을 설명할 수 있다.

- 시장 공통요인
- 산업요인
- 기업 고유요인
- 설명되지 않는 잔차

회귀분석 또는 상대수익률 모형을 사용할 수 있지만
결과를 확정적인 인과관계로 표현하지 마라.

예:

“시장·산업 요인으로 설명되는 비중 추정치: 68%”

라고 표현하고,

“주가 하락의 68%가 실제로 시장 때문에 발생했다.”

라고 단정하지 마라.

13. 시장국면 분석
==================================================

시장국면을 다음 네 단계로 분류한다.

1. 적색: 투매
2. 주황: 안정화
3. 황색: 회복
4. 녹색: 순환상승

사용 지표:

- 코스피 고점 대비 낙폭
- 코스피 20·60·120·200일 이동평균
- 반도체 바스켓 추세
- 비반도체 코스피 추세
- 동일가중 코스피 추세
- 상승종목 비율
- 20일선 위 종목 비율
- 60일선 위 종목 비율
- 시장 거래대금
- 변동성
- 기관·외국인 수급
- 공매도
- 원·달러 환율
- 배당주 바스켓 상대강도

초기 기본 규칙은 config에서 수정 가능하게 한다.

적색 예시:

- 급격한 낙폭 확대
- 신저가 갱신
- 상승종목 비율 매우 낮음
- 변동성 급등
- 외국인·기관 대규모 매도

주황 예시:

- 수 거래일 동안 신저가 중단
- 변동성 감소
- 반도체 급락 완화
- 상승종목 비율 개선
- 거래량을 동반한 저점 확인 시도

황색 예시:

- 반도체와 비반도체 지수가 함께 단기 이동평균 회복
- 시장 상승폭이 여러 산업으로 확산
- 20일선 위 종목 비율 50% 부근 이상
- 배당주 상대강도 개선

녹색 예시:

- 중기 이동평균 상승
- 배당주·금융·통신·소비재 등으로 순환매 확산
- 시장 폭과 수급이 안정
- 변동성 정상화

중요:
코스피가 삼성전자와 SK하이닉스만으로 상승하는 경우
완전한 회복으로 판단하지 마라.

다음 네 조건을 따로 표시한다.

- 반도체 회복
- 코스피 회복
- 비반도체 시장 확산
- 배당주 상대강도 회복

17. 점수 체계
==================================================

강제 필터를 통과한 종목만 점수를 계산한다.

17-1. 기본 투자매력 점수: 100점

- 배당 지속가능성: 25점
- 재무건전성·기업품질: 25점
- 산업 및 자체 역사 대비 밸류에이션: 20점
- 시장충격에 의한 할인 가능성: 15점
- 공시·뉴스 촉매: 10점
- 애널리스트·기관·외국인 참고점수: 5점

17-2. 진입준비 점수: 100점

- 현재 시장국면: 25점
- 반도체 안정화: 20점
- 비반도체 시장 확산 및 시장 폭: 20점
- 개별 종목 추세와 RSI: 20점
- 거래량·기관·외국인 수급: 15점

17-3. 데이터 신뢰도: 100점

다음을 기반으로 별도로 계산한다.

- 필수 데이터 완전성
- 최신성
- 공식 출처 여부
- 교차검증 일치 정도
- 산업 표본 수
- 뉴스·투자의견 표본 수
- 수정주가 확인 여부
- 재무 계정 매핑 성공률

데이터 신뢰도는 예상 수익률 확률이 아니다.

데이터 신뢰도가 기준 이하라면 추천을 중단한다.

초기 기본 기준:

데이터 신뢰도 70점 미만:
“분석 신뢰도 부족”

핵심 데이터 누락:
“추천 계산 불가”

17-4. 판정

초기 규칙 예시:

회복 준비 완료:
- 강제필터 통과
- 기본 투자매력 75 이상
- 진입준비 65 이상
- 데이터 신뢰도 80 이상

우량하지만 관망:
- 기본 투자매력 75 이상
- 진입준비 65 미만

과도할인 후보:
- 기본 투자매력 70 이상
- 시장충격 할인점수 70 이상
- 기업 고유 악재 확인되지 않음
- 진입준비가 낮아 추가 확인 필요

일반 검토:
- 기본 투자매력 60~74

투자배제:
- 강제필터 실패
- 기본 투자매력 60 미만
- 핵심 데이터 부족

점수 기준과 가중치는 config 파일에서 수정 가능하게 하고,
score_version을 저장한다.

백테스트 결과 없이 가중치를 최적이라고 주장하지 마라.

18. 분할매수 계획

목표 편입금액을 다음처럼 분할할 수 있다.

- 1차: 15%
- 2차: 25%
- 3차: 35%
- 4차: 25%

초기 조건 예시:

1차:
- 기본 투자매력 기준 통과
- 강제필터 통과
- 시장 투매 중이지만 기업가치 훼손 없음
- 전체 목표금액 중 소액만 진입

2차:
- 개별 종목 신저가 중단
- RSI 안정화
- 거래량 정상화
- 지지구간 확인

3차:
- 반도체와 코스피 안정화
- 비반도체 시장 확산
- 시장국면이 회복 단계 진입

4차:
- 배당주 상대강도 회복
- 중기 추세 확인
- 실적·배당 투자논리 재확인

다음이 발생하면 남은 분할매수를 취소한다.

- 감사의견 악화
- 배당 삭감 또는 중단
- 영업이익·현금흐름 급격한 악화
- 유상증자 등 주주가치 희석
- 최초 투자논리 훼손
- 거래정지·관리종목 지정
- 중대한 횡령·배임·소송

각 회차에는 단순한 가격만 제시하지 말고
실행 조건과 취소 조건을 함께 표시한다.

- 배당주 30%

- 배당주 55%

- 배당주 70%

- 단일 산업 최대 25%

- 진입준비 점수
- 데이터 신뢰도
- 변동성
- 종목 간 상관관계
- 산업 집중도
- 유동성
- 시장국면
- 현재 보유종목과의 중복

같은 기업의 보통주와 우선주를 별개 종목으로만 보지 말고
기업단위 위험도 함께 계산한다.

20. 보유·매도 판단
==================================================

매수 기능만 만들지 말고 보유·매도 판단도 제공한다.

즉시 재검토 또는 매도 경고:

- 거래정지

22. 백테스트
==================================================

실제 투자에 참고하려면 백테스트 기능이 반드시 필요하다.

다음 오류를 방지한다.

- 미래정보 참조
- 생존편향
- 수정주가 미반영
- 상장폐지 종목 누락
- 보고서 제출일 이전 재무정보 사용
- 정정공시의 과거 소급 사용
- 배당을 수익률에서 누락
- 거래비용 누락

재무정보는 결산일이 아니라
실제 공시 제출일 다음 거래일부터 사용할 수 있게 한다.

추천 시점 이후 다음 거래 가능가격으로 체결을 가정한다.

백테스트 지표:

- 누적수익률
- 연환산수익률
- 배당 포함 총수익률
- 코스피 대비 초과수익률
- 고배당지수 대비 초과수익률
- 최대낙폭
- 변동성
- 샤프지수
- 승률
- 손익비
- 회전율
- 거래비용
- 배당 삭감 종목 비율
- 추천 후 1개월·3개월·6개월·1년 성과
- 시장국면별 성과
- 산업별 성과

워크포워드 검증을 사용한다.

가중치와 기준을 전체 과거기간에 맞춰
과최적화하지 마라.

백테스트가 불완전하면
“생존편향이 제거된 결과”라고 주장하지 말고
현재 데이터의 한계를 명시한다.

28. 완료 판정 기준
==================================================

다음 조건을 모두 충족해야 MVP가 실제 작동한다고 판단한다.

1. 종목명 또는 코드 검색이 가능하다.
2. 실제 코스피 종목 여부를 확인한다.
3. ETF·ETN 등은 실제 종목분류로 제외된다.
4. 실제 최근 가격과 기준시각이 표시된다.
5. 실제 최근 감사의견이 표시된다.
6. 실제 최근 5년 배당내역이 표시된다.
7. 실제 재무제표로 TTM 지표를 계산한다.
8. 실제 수정가격으로 RSI를 계산한다.
9. 산업 평균 PER·PBR을 현재 코스피 종목으로 직접 계산한다.
10. 최근 시장 고점과 낙폭을 실제 가격으로 계산한다.
11. 반도체와 비반도체 시장 흐름을 분리한다.
12. 추천하기 버튼이 실제 종목을 분석한다.
13. 추천에서 제외된 종목의 사유가 표시된다.
14. 모든 중요 숫자에 출처와 기준일이 표시된다.
15. 데이터가 없을 때 가짜 숫자가 나타나지 않는다.
16. 같은 데이터와 같은 규칙으로 같은 결과가 재현된다.
17. AI가 재무 숫자나 종합점수를 임의로 만들지 않는다.
18. API 오류를 정상 데이터처럼 처리하지 않는다.
19. 실제 API 호출 성공 여부가 로그로 확인된다.
20. 자동주문 없이 읽기 전용 투자 의사결정 지원도구로 작동한다.

==================================================
29. 첫 개발 응답에서 해야 할 일
==================================================

이 프롬프트를 받은 뒤 곧바로 가짜 완성 화면을 만들지 마라.

첫 번째 작업에서 다음을 수행하라.

1. 전체 요구사항을 기능 단위로 정리한다.
2. 공식 데이터별 필드 매핑표를 만든다.
3. 실제 제공 가능한 데이터와 제공이 어려운 데이터를 구분한다.
4. API endpoint와 응답 필드를 공식 문서로 검증한다.
5. 프로젝트 폴더 구조를 생성한다.
6. 환경변수와 데이터베이스 구조를 생성한다.
7. KRX, OpenDART, 한국투자증권 provider의 기본 코드를 작성한다.
8. API 연결상태 점검 화면을 만든다.
9. 실제 데이터가 연결되지 않은 상태에서는 숫자를 표시하지 않는다.
10. Phase 1의 종목 검색 기능부터 실행 가능한 코드로 구현한다.

설명이나 의사코드만 제시하지 말고 실제 파일을 작성하라.

각 구현이 끝날 때마다 다음을 보고하라.

- 생성한 파일
- 실제 실행한 명령
- 테스트 결과
- 실제 API 연결 결과
- 현재 확인된 데이터 기준일
- 미완료 기능
- 데이터상 제약
- 다음 구현 단계

실제 API 호출을 실행하지 못했다면
“구현 완료”가 아니라 “연결 미검증”이라고 정확히 표현하라.
