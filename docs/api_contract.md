# 공식 API 계약 검증서

## 1. 문서 목적과 판정 원칙

- Phase 0A 범위에서 공식 제공기관 문서로 확인한 계약만 기록한다.
- 문서 검토 시각은 `2026-07-28 Asia/Seoul`이다.
- `실제 endpoint`가 `미확인`인 행은 공개 기능의 존재만 확인했거나 공개 API 계약을 찾지 못한 경우다. 이 값을 근거로 provider를 구현해서는 안 된다.
- 응답 필드는 공식 명세에 표시된 이름만 적었다. 예시 응답이나 다른 서비스의 관례에서 필드명을 추정하지 않았다.
- 단위가 명세에 없으면 필드명으로 단위를 추정하지 않고 `공식 명세 단위 미표기`로 기록했다.
- 현재 환경에는 대상 기관의 인증정보가 설정되어 있지 않다. 따라서 인증이 필요한 실제 API 호출은 수행하지 않았고, 성공을 주장하지 않는다.
- 인증정보가 있는 실제 호출을 수행하는 Phase에서는 원응답을 `api_raw_responses`의 논리 구조에 맞춰 `provider`, `기능명`, 인증정보를 제거한 요청 파라미터 해시, 수신시각, HTTP 상태, 원응답, 응답 해시, 데이터 기준일과 함께 보존해야 한다.

## 3. 기관별 공통 제약과 라이선스 주의

### KRX

- 회원가입, 인증키 신청 승인, 개별 API 사용 신청 승인이 필요하다.
- 인증키는 발급일부터 1년이며 연장 절차가 있다.
- Open API 약관상 비상업적 이용, 출처 표시, 제3자 재제공 제한이 있다. 재배포·영리 목적 또는 실시간·지연 시세 이용은 KRX Data Marketplace의 별도 데이터 이용계약 여부를 확인해야 한다.
- 수치 단위가 기능 명세에 명시되지 않은 계약은 실제 응답과 별도 공식 데이터 사전으로 검증하기 전 정규화하지 않는다.

### OpenDART

- 서비스키는 회원별로 발급되며 제3자에게 제공해서는 안 된다.
- 공시 제출자가 작성한 자료이므로 금융감독원이 정확성·완전성을 보증하지 않는다는 약관상 유의가 있다.
- 정정공시는 원본을 덮어쓰지 않고 접수번호별로 모두 보존한다.
- 재무·배당 숫자는 공시 원문, 보고서 구분, 연결·별도, 단위와 기간을 함께 검증한다.

### 한국투자증권

- 계좌의 앱키·앱시크릿과 OAuth 접근토큰이 필요하다. 일반고객 접근토큰 유효기간은 공식 계약에 1일로 표시되어 있다.
- REST 현재가 조회는 실시간 WebSocket과 다르며 수집시각을 함께 저장해야 한다.
- 현재 공식 유량 공지는 실전 REST 계좌당 초 18건, 모의 초 1건이다. 호출량 정책은 변경될 수 있으므로 실행 전 공지를 다시 확인해야 한다.
- 본 프로젝트는 읽기 전용이다. 주문·정정·취소·계좌 쓰기 API는 계약 검증 및 구현 대상에서 제외한다.

### KIND

- 공식 사이트의 제공 화면은 확인했으나 별도의 공개 API 개발문서, 인증 방식, endpoint, 응답 필드, 호출 제한을 확인하지 못했다.
- 화면 내부 통신 경로나 HTML 폼 경로를 공개 API 계약으로 승격하지 않는다.
- 자동 수집·대량 이용은 KRX와의 별도 계약·권한 및 이용조건 확인 전 보류한다.

### NAVER

- 2026-06-25 NAVER API HUB가 출시됐고 뉴스 검색의 새 공식 계약이 공개됐다.
- 개발자센터 Search API 신규 신청은 2026-07-30 24:00에 중단되고, 기존 신청은 2027-06-30 24:00까지 지원된다.
- 뉴스 검색은 기사 본문이 아니라 제목과 요약 패시지를 제공한다. 원문 전체를 읽은 것처럼 분석하지 않는다.
- 기사 저작권과 원문 링크를 존중하고 응답을 무기한 재배포 가능한 데이터로 간주하지 않는다.

### 한국은행 ECOS

- 인증키 유효기간은 공식 이용조건에 2년으로 안내되며 연장할 수 있다.
- `UNIT_NAME`과 `TIME`을 원자료에 함께 저장해야 한다.
- 상업적 이용 제한 표시가 있는 통계는 원 통계작성기관의 별도 승인이 필요할 수 있고, ECOS 출처를 표시해야 한다.
- 서비스 전체의 단일 갱신시각은 없으며 통계표별 공표주기를 따른다.
